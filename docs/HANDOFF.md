# 交接筆記（2026-10-02）

給接手的 Claude Code 工作階段。先讀 `README.md` 和 `docs/ROADMAP.md`，再讀這份。

## 使用者與工作方式

- 使用者是家長，工具給 8 歲孩子用（用滑鼠操作）。UI 文字一律繁體中文、按鈕大、字少、不用術語；所有模擬都標「這是示意，最後以實際射出為準」。
- 每個階段（或每個明確的功能）做完就停下來，用繁體中文回報：做了什麼、怎麼執行和測試、已知限制。使用者確認後才繼續。
- 使用者不太會描述幾何，常常給截圖。截圖路徑可以直接用 Read 打開。
- 遇到需要使用者決定的事先問，不要自己猜。使用者的實體實驗結果（見 ROADMAP 階段 6）是判斷物理效果「要不要做」的依據：實驗沒看到的效果不要放進畫面（例如「翼片延後失速」就刻意沒做）。

## 規則

- 摺紙核心（`src/core/model`、`engine`、`planners`、`validate`）的資料結構不要改；`PaperState` 永遠是理想的攤平狀態。3D、翼片翹起、風洞都是從它「推導」出來的。
- 核心邏輯放 `src/core/`，純函式、不碰 DOM、要寫測試；UI 放 `src/ui/`。
- 不要使用 GPL 程式碼（Rabbit Ear、OriSim3D 都是 GPL-3.0，只能參考概念）。
- 不要 `git push`、不要改寫歷史。使用者有時會在你做到一半時自己 commit（例如 `450a895 顯示`），就在它上面接著 commit。commit 訊息用英文，結尾加 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。
- 完成一個功能要更新 `docs/ROADMAP.md`。

## 今天做了什麼

### 1. 「看飛機」3D 預覽：不透明、只看得到最外層（`aaa1bc8`）

- 問題：疊在一起的紙在同一平面（厚度 0）互相穿透（z-fighting），底層的摺痕也露出來；而且 `Assembly` 為了重量對稱把整疊紙鏡射到左右兩邊，同一位置有兩份紙。
- 做法（只改顯示，重心／升力計算不動）：
  - `model/orders.ts` 的 `layerDepths()`：每一面的**局部**層數（壓在它下面、和它重疊的最長一串）。
  - `physics/assembly.ts` 的 `AssemblyPiece` 多了 `mirrored` 和 `up`（摺紙畫面「朝上」那側的 3D 法向量）。
  - `physics/display.ts` 的 `displayPieces()`：對摺時在下面的半張紙放右邊、上面的半張放左邊（左翼用鏡射那份、`up` 反向），每片依局部層數沿法線錯開 `PAPER_THICKNESS` = 0.15 mm。
  - `ui/plane/Preview3D.tsx`：正反兩面各一個材質（白正面／橘背面）；只畫層與層的交界（同平面、同朝向、並排在兩側的邊視為攤平摺痕，不畫）；邊線沿法線 ±0.3 倍紙厚各畫一次。
- 之前另一個工作階段試過「全域層序 × 2.5 mm」的爆炸圖（`3236a47`），使用者覺得怪，已還原（`b0b8516`）。不要再做那種大間距分層。

### 2. 點選翼片翹起（`450a895`、`701dcf0`、`614699c`）

- 在 3D 裡點一片紙（raycast，第一個打到的就是最外層）→ 選中並翹起 30°；滑桿「選到的翼片翹起 X°」0～80°；「↩️ 放下」移除；點空白處取消；點到翹不起來的紙會提示。
- 顏色：可以翹的紙平常淡淡綠色、滑鼠指著變深綠、已選取藍色（直接換材質顏色；用自發光在白紙上看不出來）。
- 拉滑桿不再重設鏡頭（只有第一次或飛機大小變化超過 25% 才重新對準）。
- **翼片 = `flapFor(state, 點的那一面)` 自動找轉軸**（`physics/assembly.ts`）：
  - 候選轉軸：點的那一面「用攤平摺痕（0°）連成的整塊」上，所有真正摺過的摺痕所在直線；都不行才考慮攤平的摺痕（例如孩子「留摺痕」壓的線）。
  - 對每條候選線：從點的那一面出發，不跨過那條線能連到的紙全部一起動（掛在上面的反摺尖角會被帶起來）。
  - 合法條件：這群紙只靠那條線和其他紙相連；只屬於原紙的同一半（3D 裡兩半各往一邊展開）；面積 ≤ 整張的 20%。
  - 選會動的紙最少的那條。結果依 `PaperState` 物件快取（WeakMap）。
- `buildAssembly(state, wingLine, dihedral, bends)` 的 `bends` 是「**根（點的那一面）→ 角度（弧度）**」。同一面在好幾片翼片裡時，先轉小片、再轉大片（大的把小的一起帶走）。翹的方向是「讓自由端往 +z」。
- `physics/flaps.ts`：
  - `FlapBend { at: 原紙座標的一點, deg }`。用原紙位置記錄，存檔、讀檔、重播後面的 id 變了也找得到。
  - `flapRoots()`：點的那一面，加上原紙上以中線鏡射位置的那一面（左右一起翹，和左右對稱的物理計算一致）。
  - `flapPartners()`／`flapFacesOf()`：會動到的所有面，給畫面發亮用。
  - `resolveFlapBends()`、`flapIndexOf()`。
- `ui/design.ts`：`Design.flaps?: FlapBend[]`（新）。`flapBendDeg` 是舊欄位，只為了讓舊存檔／實測紀錄還能打開（它只翹「單一面」的翼片）；新操作會把它設為 0。`flapKey(design)` 給 `useMemo` 當相依值。

### 3. 風洞的煙會受翹起的翼片影響（`fbde752`）

- 問題：煙的流場 `flowAt`（側視）、`topFlowAt`（俯視）只認得平板機翼，翹起翼片後煙完全不變。
- `physics/flapflow.ts`（純函式＋測試）：
  - `sideFlaps()`：每片翹起的紙片在側視是一小塊傾斜板；`lift ∝ 面積比 × sinτ·cosτ`、`drag ∝ 面積比 × sin²τ`，和 `planform.ts` 的前翼／阻力用同一套比例。
  - `rotateSideFlaps()`：跟著機翼依攻角轉。
  - `flapFlowAt()`：每片加一個小渦漩（前方上洗＝前翼升力）＋一段慢速尾流（強度隨阻力）。
  - `topFlapWakes()`／`topFlapWakeAt()`：俯視每片翼片後方的尾流帶。
  - 沒翹起任何翼片時，流場和以前完全一樣（有測試）。
- `ui/windtunnel/WindTunnel.tsx`：煙不會穿過翹起的翼片（`noPenetrateSegment`，從上面滑過去）；翼片尾流加亂流、上暖色；有翹起時多一行提示。

## 已知限制（可能是下一步）

- 同一個位置只有一種翹法（自動選最小的那片），孩子不能自己挑轉軸。可以考慮「再點一次換下一條轉軸」。
- 翼片橫跨機翼摺線時，機身那段和機翼那段各繞自己的軸轉，會分開。預設機翼位置（45%）下，孩子原型機的機頭翼片就是這樣，會從機身側面翹出去；把「機翼位置」往中線拉比較像實體飛機。
- 對摺後又把左右兩半一起摺（例如摺角包住兩層）時，3D 分左右兩邊只是近似。
- 風洞尾流的長度、寬度、減速多少是調出來看趨勢的數字；翼片很大時尾流會蓋滿整個機翼。
- 「左右比較穩」的效果還沒有表現，留給階段 7。
- 下一個計畫中的工作是階段 7（飛行模擬），見 `docs/ROADMAP.md`。開工前先跟使用者確認。

## 驗證方法（每次都要做）

1. `npm test`（目前 15 個檔、135 個測試）和 `npm run build` 都要通過。
   - `tests/history.test.ts` 的「隨機亂摺」很吃 CPU，已給 30 秒上限；整套平行跑若偶爾逾時，不是你的錯。
2. 實際操作 UI：
   - 在系統暫存資料夾 `npm install playwright-core`，用 `chromium.launch({ channel: 'chrome', headless: true, args: ['--use-angle=swiftshader', '--enable-unsafe-swiftshader'] })`（Three.js 需要 WebGL）。
   - 開發伺服器：`npx vite --port 5199 --strictPort` 背景啟動，輪詢到能連上；結束時用 `netstat -ano` 找 PID、`taskkill //PID <pid> //T //F`。使用者自己用的是 5173。
   - 摺紙畫布的座標換算（A4、還沒摺時）：`k = min(w / (210 + 2m), h / (297·1.21))`，`m = 0.06·297`，`ox = w/2`，`oy = (h − k·(297·1.21)) / 2 + k·(297 + 2.5m)`；螢幕點 = `(ox + k·x, oy − k·y)`（相對 `canvas.editor`）。
   - 孩子原型機的操作步驟：「邊對邊」點上緣 (-60, 297) 再點中線 (0, 120) → ✅ 摺！；開「🔀 反摺」、「點對點」點 (0.5, 192.5) 再點 (35, 255) → 選「只摺最上面那片」；關反摺 → 「對摺」→「看飛機」。
   - 3D 裡要點翼片時，翼片的螢幕位置不好預測：讓腳本掃過畫布，讀 `canvas.style.cursor`，等於 `'pointer'` 的地方就是可以點的翼片。
   - 一定要實際看截圖，並確認 console 沒有錯誤。
3. Windows 上用 Bash 工具時，不要把 heredoc 和其他直譯器混用（曾經卡住一個 `python - <<'PY'`）；要寫腳本就直接寫成檔案。
4. 背景啟動的開發伺服器最多跑 2 小時就會被停掉。
